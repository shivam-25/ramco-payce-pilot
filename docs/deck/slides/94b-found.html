WHAT MEASUREMENT FOUND THAT REVIEW DID NOT

Six defects. All of them mine.

The abstain threshold compared two different scales

Rank-fusion scores sit near 0.016; the floor was a 0.55 cosine similarity. Everything looked irrelevant, so everything escalated.

Similarity cannot tell answerable from unanswerable

Measured: answerable 0.20–0.65, unanswerable 0.28–0.50. The distributions overlap almost entirely, so no threshold works. Abstention moved to the model, verified in code.

The prior-period chunk named its own replacement

A chunk describing June also said “replaced by 25,000”. The model read the new value off it and quoted it.

The cache ignored time

September matched June at 0.958 and was served June’s answer — the original incident, reintroduced by an optimisation. Entries now carry a validity window. Gate G8.

A cited pointer passed as an answer

“The rate is in KB-0140, see Confluence.” Also why Ragas scored faithfulness 0.756: a claim about where an answer lives is still an unsupported claim.

The PII gate understated its own work

Notes buried in event histories were masked correctly and then reported as “no personal data found”. The quiet direction of error.

Four of the six were found by a test the code had just passed — the argument for gates with numbers rather than a review with opinions. A seventh is on the next slide, and no gate caught it: the pilot invented product behaviour, and I only found it by typing a ticket into the console. Gates catch what you thought to measure. Using the thing catches the rest.
