APPENDIX  ·  MULTI-TENANCY

Scoping is a predicate, not a filter in the browser.

A signed-in organisation sees its own tickets and can resolve one. The organisation id comes from an HMAC-signed httpOnly cookie read on the server — never from the request body.

The isolation test is the middle row. A valid ticket id held by the wrong organisation matches no row, and the call says it changed nothing rather than reporting a success it did not perform.

The statement that carries it

UPDATE tickets
   SET status = %s, resolved_at = %s
 WHERE ticket_id   = %s
   AND customer_id = %s

Served text is already masked. subject_masked and body_masked are what the loader writes, and it raises rather than insert a row still carrying an identifier. The portal reads no raw column because there is no raw column.

One write, and it is honest about itself. The database user is the instance master — “read only” here means the drafting code contains no statement that writes. This one is confined to a single module, two columns, scoped by organisation, unreachable from the drafting path.
